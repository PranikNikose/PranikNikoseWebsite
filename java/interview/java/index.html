Q1. What is Java and what are its main features? Why do we choose Java?
✓ Asked ×1
Java is a high-level, object-oriented, platform-independent language. It follows WORA (Write Once, Run Anywhere) through the JVM. Main features: Platform Independent (bytecode + JVM), Object-Oriented, Secure (no explicit pointers, class loader/bytecode verifier/security manager), Robust (strong exception handling + type checking), Portable, Multithreaded, High Performance (JIT compiler), Automatic Garbage Collection, Distributed and Dynamic. For a Spring Boot role, mention: strong ecosystem (Spring/Hibernate), mature concurrency model, and huge enterprise adoption for backend/microservices.
Q2. Why is Java called platform independent?
✓ Asked ×1
Source code compiles to bytecode (.class), not native machine code. Bytecode runs on the JVM rather than directly on the OS. Since a JVM implementation exists for every major OS, the same bytecode runs anywhere without recompilation — the WORA principle. (Note: the JVM itself is platform-dependent; it's the bytecode that's portable.)

Integer Cache Trap (frequently asked as trivia): Integer a=100,b=100; a==b → true (both point to the same cached object, range -128..127). Integer a=200,b=200; a==b → false (new heap objects outside cache range). Always use .equals() to compare wrapper values, never ==.

Q3. Integer caching — why does Integer a=128,b=128 give a==b → false?
✓ Asked ×1
Integer values between -128 and 127 are cached by the JVM (Integer.valueOf() reuses instances from the internal IntegerCache), so a==b is true in that range because both references point to the same cached object. Outside that range, autoboxing creates new Integer objects, so == compares references and returns false. Always use .equals() to compare Integer values.
Q4. Explain time/space complexity (Big-O) in general terms.
✓ Asked ×1
Big-O describes how an algorithm's time or space requirement grows as input size (n) grows. Time complexity = how execution work scales; space complexity = how extra memory usage scales. Examples: ArrayList.get(i) is O(1) (array index), linear search is O(n), binary search is O(log n), HashMap get/put is amortized O(1), TreeMap get/put is O(log n) (Red-Black Tree).

Q9. What are the four pillars of OOP?
✓ Asked ×1
Encapsulation provides data hiding by keeping variables private and exposing them via getters/setters. Inheritance promotes code reusability — child class inherits parent's properties/behavior. Polymorphism provides flexibility — the same method behaves differently depending on the object. Abstraction hides implementation details, exposing only required functionality. Sample interview line: "I used encapsulation in POJOs, inheritance for reusability, polymorphism through interfaces, and abstraction through interface-implementation design." 
public class Account {                       // Encapsulation
  private double balance;                  // private field
  public double getBalance() { return balance; }
}
class SavingsAccount extends Account {}  // Inheritance (IS-A)
interface Shape { double area(); }             // Abstraction
class Circle implements Shape {
  public double area() { return ...; }         // Polymorphism (override)
}
Q10. What is encapsulation?
✓ Interview Asked
Encapsulation is the process of wrapping data and methods into a single unit called a class, and providing data hiding by controlling access to that data through methods. Achieved by declaring fields private and exposing controlled access via getter/setter methods.
Q11. What is inheritance?
✓ Interview Asked
Inheritance is the mechanism by which a child class inherits the properties and behavior of a parent class — promotes code reusability. Java supports Single, Multilevel, and Hierarchical inheritance through classes; Multiple Inheritance is achieved only via interfaces.
Q12. What is polymorphism?
✓ Interview Asked
Polymorphism means one object can behave in different forms depending on context — e.g. a man can act as a father, employee, or patient in different situations. Achieved via Compile-time Polymorphism (Method Overloading) and Runtime Polymorphism (Method Overriding, via Dynamic Method Dispatch).
Q13. What is abstraction?
✓ Interview Asked
Data Abstraction is hiding implementation details and showing only necessary details to the user. Achieved using Abstract Classes and Interfaces.
Q14. Why does Java not support multiple inheritance through classes?
💼 LinkedIn Asked
To avoid ambiguity and the Diamond Problem — if a child class inherits the same method from two parent classes, it's unclear which implementation should execute when called via the child object. Java sidesteps this by disallowing multiple class inheritance and instead allowing multiple interface implementation; if two interfaces have conflicting default methods, the implementing class is forced to explicitly override and resolve it. 
interface A { default void greet(){ System.out.println("A"); } }
interface B { default void greet(){ System.out.println("B"); } }
class C implements A, B {
  public void greet() {          // must override — compile error otherwise
    A.super.greet();       // explicitly pick one, or write custom logic
  }
}
Q15. If two interfaces have the same default method, how do you resolve it when a class implements both?
💼 LinkedIn Asked
Java forces the implementing class to override that method explicitly (diamond conflict) — otherwise it won't compile. Inside the override, call a specific interface's version using InterfaceName.super.methodName() (see code sample above, Q14).
Q16. What is composition, how is it different from inheritance, and when do you prefer it?
✓ Asked ×1
Composition is a HAS-A relationship where a class contains another class as a member — e.g. Car HAS-A Engine. Inheritance is an IS-A relationship — e.g. Dog IS-A Animal. Prefer composition when there's a HAS-A relationship rather than a true IS-A relationship — it provides better flexibility, looser coupling, and easier maintenance ("favor composition over inheritance" is a widely-cited design principle). 
class Engine { void start(){} }
class Car {
  private final Engine engine;      // Composition — Car HAS-A Engine
  Car(Engine engine) { this.engine = engine; }
  void start() { engine.start(); }   // delegates, not inherits
}

Q18. What is a constructor? Can a constructor be final or static?
✓ Asked ×1
A constructor is a special member used to initialize an object's state. It has the same name as the class, no return type, and is auto-invoked on new. Access modifiers are allowed on a constructor, but non-access modifiers (final, static, abstract) are not allowed — a constructor isn't inherited or overridden, so "final"/"static" have no meaning for it.
Q19. What is a Generic Enum? Can Enums be generic?
✓ Asked ×1
Enum = special data type used to define a fixed set of constants; type-safe; introduced in Java 5; can have fields, methods, constructors; extends java.lang.Enum; cannot be instantiated with new. Enums cannot be generic (an enum's constants are its own fixed type parameter), but they can contain generic methods. 
enum Status {
  ACTIVE, INACTIVE;
  public static <T> T describe(T value) { return value; } // generic method OK
}
Q20. What are Generics and why were they introduced?
✓ Asked ×2
Generics let classes, interfaces, and methods work with different data types while providing compile-time type safety. Introduced to avoid explicit casting and ClassCastException at runtime. 
List<String> list = new ArrayList<>();  // compile-time checked, no cast needed on get()
String s = list.get(0);                    // vs raw List → Object → needs (String) cast
Q21. Difference between Cloneable and Runnable?
✓ Asked ×1
Cloneable is a marker interface (no methods) indicating an object can be cloned via Object.clone() — without it, clone() throws CloneNotSupportedException. Runnable is a functional interface (run()) defining a task that can be executed by a thread.
Q22. How does getter/setter participate in immutability?
✓ Asked ×1
A getter is allowed because it only reads data (doesn't change state); a setter is not allowed in an immutable class because it would change the state after construction. Immutable classes expose only getters.
Q23. Shallow Copy vs Deep Copy
✓ Asked ×1
Shallow copy copies references — nested/mutable objects are shared between original and copy (mutating one affects the other). Deep copy creates independent copies of nested objects — fully isolated. 
// Shallow: default Object.clone() copies field references as-is
// Deep: manually clone nested mutable fields too
class Employee implements Cloneable {
  Address address;
  protected Employee clone() throws CloneNotSupportedException {
    Employee copy = (Employee) super.clone();
    copy.address = new Address(this.address);  // deep-copy the mutable field
    return copy;
  }
}

4String, Memory & Immutability
Q25. Why are Strings immutable? Why immutable from a security perspective?
💼 LinkedIn Asked
Once a String object is created, its value cannot change. Immutability provides: Security — sensitive data (file paths, URLs, DB connection strings) stored as Strings can't be maliciously/accidentally altered after creation; Thread Safety — safely shared across threads without synchronization; String Pool reuse — safe to share the same object for equal literals, saving memory; Performance — hashCode is cached, making Strings fast as HashMap keys. 
String s1 = "Java";                 // String Constant Pool — reused if value exists
String s2 = new String("Java");      // forces a NEW heap object, separate from pool
System.out.println(s1 == s2);      // false — different references
System.out.println(s1.equals(s2)); // true  — same content
System.out.println(s2.intern() == s1); // true — intern() returns the pooled reference
Q26. How would you create an immutable object / class?
💼 LinkedIn Asked ✓ Asked ×1
Make the class final, declare all fields private final, initialize only via the constructor, provide no setters, and use defensive copies for mutable fields (collections, dates, etc.) both on the way in and the way out. Once created, the object's state cannot change. 
public final class Employee {
  private final String name;
  private final List<String> skills;

  public Employee(String name, List<String> skills) {
    this.name = name;
    this.skills = new ArrayList<>(skills);      // defensive copy IN
  }
  public List<String> getSkills() {
    return Collections.unmodifiableList(skills); // defensive copy/view OUT
  }
  // no setters — String/wrapper fields, records, and Java built-in immutables follow this pattern
}
Benefits: thread-safe, simple, secure, cache-friendly, reliable. Examples: String, wrapper classes, record (Java 16+, auto-generates ctor/getters/equals/hashCode/toString).

Q27. What are checked exceptions? When should they be used?
💼 LinkedIn Asked
Checked exceptions are checked by the compiler at compile time and must be handled (try-catch) or declared (throws). Examples: IOException, SQLException. Use them when the caller can realistically recover and take corrective action — commonly file handling, database access, or network operations.
Q28. Difference between throw and throws?
✓ Asked ×1
throw explicitly throws an exception instance from within a method body. throws declares in a method signature that it might throw an exception — doesn't itself throw anything. 
void readFile() throws IOException {   // throws — declares
  if (file == null)
    throw new IllegalArgumentException("file is null"); // throw — actually throws
}
Q29. If both the try and finally blocks return/throw, which wins?
✓ Asked ×2
The finally block always executes, and its return value or exception overrides the one from try. This is a common trap — avoid returning from finally in real code as it silently swallows the try block's outcome. 
static int test() {
  try { return 1; }
  finally { return 2; }   // this wins → method returns 2, the try's "return 1" is discarded
}
Also: Throwable can technically be caught (parent of Exception & Error) but avoid it — it also swallows serious JVM Errors that app code shouldn't handle. Never silently swallow exceptions.
Q30. Try-With-Resources — how does close() work internally, and which interface must a resource implement?
✓ Asked ×3
Try-With-Resources (Java 7+) automatically closes resources after execution. Works with classes implementing AutoCloseable (or its stricter subtype Closeable). Internally, the compiler generates an implicit finally block that calls close() on each declared resource, in reverse order of declaration — even if an exception is thrown from the try body. 
try (BufferedReader br = new BufferedReader(new FileReader("file.txt"))) {
  return br.readLine();
}  // br.close() auto-invoked, no explicit finally needed
If the resource's close() throws while an exception is already propagating from the try body, the close() exception is attached as a suppressed exception on the primary one (retrievable via getSuppressed()).
Q31. How would you create custom exceptions and design an exception hierarchy for an app?
💼 LinkedIn Asked
Extend Exception (checked) or RuntimeException (unchecked) for business-specific errors — in Spring Boot, RuntimeException subclasses are the standard since they don't force callers to handle them everywhere. Build a common base exception → categorize into Validation / Business / System subclasses; handle centrally via @RestControllerAdvice + @ExceptionHandler. 
public class BusinessException extends RuntimeException {
  public BusinessException(String msg) { super(msg); }
}
public class UserNotFoundException extends BusinessException {
  public UserNotFoundException(Long id) { super("User not found: " + id); }
}

@RestControllerAdvice
public class GlobalExceptionHandler {
  @ExceptionHandler(UserNotFoundException.class)
  public ResponseEntity<ErrorResponse> handle(UserNotFoundException ex) {
    return ResponseEntity.status(HttpStatus.NOT_FOUND).body(new ErrorResponse(ex.getMessage()));
  }
}

6Collections Framework
Q32. What is the Collection Framework?
💼 LinkedIn Asked
A set of interfaces and classes used to store and manage a group of objects as a single entity. Provides data structures like List, Set, Queue, and Map, plus algorithms (sorting, searching) over them.
Q33. Difference between List and Set?
✓ Asked ×1
List: allows duplicates, preserves insertion order, supports index-based access. Set: unique elements only; order depends on implementation (HashSet = none, LinkedHashSet = insertion order, TreeSet = sorted order).
Q34. Difference between ArrayList and LinkedList?
✓ Asked ×1 ✓ Asked ×2 (internals)
ArrayList: dynamic array structure; grows ~50% when full and copies elements; random access is O(1); insert/delete in the middle is slow (must shift elements); not thread-safe. LinkedList: doubly linked list; random access is slow (must traverse — O(n)); insert/delete in the middle is fast (just pointer changes, O(1) once positioned).
Q35. Array vs ArrayList
✓ Asked ×1
Array: fixed size, stores primitives and objects, index-based. ArrayList: dynamic size, stores objects only (autoboxing for primitives), index-based, rich built-in API (add/remove/search).
Q36. What is HashMap? How does HashMap work internally? (High-Frequency Question)
✓ Asked ×7
HashMap is an implementation of the Map interface that stores data as key-value pairs, internally backed by an array of buckets. put(key, value): calculate hashCode(key) → determine bucket index (hash & (capacity-1)) → if the bucket is empty, store directly → if occupied (collision), entries chain into a LinkedList; from Java 8, if a bucket's node count exceeds 8, the LinkedList converts to a Red-Black Tree for O(log n) worst case instead of O(n). get(key): uses hashCode() to locate the bucket, then equals() to find the exact matching key/entry. Resizing/rehashing: when entries exceed capacity × loadFactor (default load factor 0.75), HashMap doubles its internal array size and rehashes every existing entry into the new buckets (since bucket index depends on capacity). 
HashMap<String, Integer> map = new HashMap<>();
map.put("a", 1);       // hash("a") → bucket index → store
map.get("a");          // hash("a") → bucket → equals() scan → return 1
Q37. Difference between HashMap and Hashtable?
✓ Asked ×3
HashMap: not thread-safe, allows 1 null key + multiple null values, faster (no sync overhead). Hashtable: synchronized & thread-safe, doesn't allow null keys/values, slower (whole-map lock), legacy class.
Q38. What is ConcurrentHashMap? Internal working? Why does it not allow a null key?
✓ Asked ×4
A thread-safe Map allowing multiple threads to read & update concurrently. Uses bucket/node-level locking plus CAS (Compare-And-Swap) instead of a single whole-map lock, giving much better concurrency than Hashtable/Collections.synchronizedMap. It disallows null keys/values because if get() returns null, in a concurrent context you can't distinguish "the key is missing" from "the key maps to null" — that ambiguity is unsafe under concurrent mutation.
Q39. HashMap vs ConcurrentHashMap
✓ Asked ×2
HashMap: not thread-safe, not synchronized, 1 null key allowed, fastest in single-threaded apps. ConcurrentHashMap: thread-safe (bucket/node-level locks + CAS), no null key/value allowed, best throughput in multi-threaded apps.
Q40. HashMap vs TreeMap
✓ Asked ×2
HashMap: key-value, no ordering guarantee, 1 null key allowed, not thread-safe, O(1) average ops. TreeMap: key-value, keys sorted (Red-Black Tree, natural order or supplied Comparator), no null key allowed, not thread-safe, O(log n) ops.
Q41. What is Hashtable?
✓ Asked ×1
Key-value pair map, synchronized & thread-safe, no null key/value allowed, legacy (pre-Collections Framework), whole map locked on every operation — largely superseded by ConcurrentHashMap in modern code.
Q42. Why is LinkedHashMap needed?
✓ Asked ×1
LinkedHashMap gives HashMap's fast average O(1) performance while also maintaining predictable insertion order (or optionally access order, useful for building an LRU cache via removeEldestEntry).
Q43. ArrayList Internal Working
✓ Asked ×2
ArrayList internally uses a dynamic array. When full, it grows by ~50% (newCapacity = oldCapacity + (oldCapacity >> 1)) and copies existing elements into the new array. Provides fast O(1) index-based retrieval.
Q44. What is HashSet? If made synchronized, does it become fail-safe?
✓ Asked ×1
HashSet is a Set implementation storing unique elements with no insertion-order guarantee (internally backed by a HashMap — element = key, a shared dummy constant = value). No — wrapping a HashSet with Collections.synchronizedSet() does not make its iterator fail-safe; it's still fail-fast and throws ConcurrentModificationException if structurally modified during iteration by another thread. Synchronization only serializes access, it doesn't change iterator semantics.
Q45. What is Fail-Fast vs Fail-Safe Iterator?
✓ Asked ×4
Fail-Fast: throws ConcurrentModificationException if the collection is structurally modified while iterating (ArrayList, HashMap, HashSet — detected via an internal modCount check). Fail-Safe: does not throw, because it iterates over a copy/snapshot of the collection — e.g. CopyOnWriteArrayList, CopyOnWriteArraySet, ConcurrentHashMap (any concurrent collection). 
List<Integer> list = new ArrayList<>(List.of(1,2,3));
for (int x : list) {
  if (x == 2) list.remove(Integer.valueOf(2)); // throws ConcurrentModificationException
}
Q46. What is ConcurrentModificationException?
💼 LinkedIn Asked
A runtime exception thrown when a collection is structurally modified (add/remove) while being iterated, other than through the iterator's own remove(). Fix: use Iterator.remove(), or iterate over a copy, or use a concurrent/fail-safe collection.
Q47. Significance of hashCode() and equals()?
💼 LinkedIn Asked
hashCode() → locates the bucket. equals() → finds the exact matching object within that bucket. Both must be overridden together for hash-based collections (HashMap/HashSet) to behave correctly.
Q48. If two objects are equal, do they always have the same hashCode? If they have the same hashCode, are they always equal?
✓ Asked ×1
Equal objects (per equals()) must have the same hashCode (contract requirement). But objects with the same hashCode are not necessarily equal — a hash collision can put two unequal objects in the same bucket, and only equals() disambiguates.
Q49. How to correctly override equals()/hashCode() — full walkthrough
✓ Asked ×1
Override equals() to check type and compare all significant fields (using Objects.equals() for null-safety). Override hashCode() using Objects.hash() on those same fields, so equal objects always produce the same hash code. 
public class Employee {
  private final Long id;
  private final String email;

  @Override public boolean equals(Object o) {
    if (this == o) return true;
    if (!(o instanceof Employee)) return false;
    Employee e = (Employee) o;
    return Objects.equals(id, e.id) && Objects.equals(email, e.email);
  }
  @Override public int hashCode() {
    return Objects.hash(id, email);
  }
}
Q50. Can we use a custom class as a HashMap key?
✓ Asked ×1
Yes, provided equals() and hashCode() are correctly overridden. Fields used for key comparison should ideally be immutable — if a key's hash-relevant fields mutate after insertion, the entry becomes unreachable at its original bucket (a very common production bug source).
Q51. Why can HashSet fail to detect duplicates if equals()/hashCode() are badly implemented?
💼 LinkedIn Asked
If equals() and hashCode() are inconsistent (e.g. hashCode() always returns a constant while equals() only sometimes returns true, or vice versa) — HashSet can fail to detect true duplicates, or waste time treating unequal objects as potential duplicates in the same bucket. Violating the contract breaks Set's uniqueness guarantee entirely.
Q52. How do you avoid hash collisions in a HashMap?
💼 LinkedIn Asked
Use a well-distributed hashCode() implementation (e.g. via Objects.hash() combining multiple fields, rather than a constant or narrow-range value), choose an appropriately-sized initial capacity to reduce bucket crowding, and avoid mutable fields in the hashCode computation.
Q53. Why are Set elements unique, and how do heterogeneous/custom objects sort in a TreeSet?
✓ Asked ×1
Set enforces uniqueness via equals()/hashCode() (HashSet) or compareTo()/Comparator (TreeSet) — elements are treated as duplicates if these return 0/true. For heterogeneous or custom objects in a TreeSet, you must supply a Comparator or implement Comparable, since TreeSet relies purely on ordering, not equals(), to detect duplicates (two elements comparing as 0 are considered the same).
Q54. Difference between Comparable and Comparator?
💼 LinkedIn Asked
Comparable: natural sort order, implements compareTo(), single sort logic, defined inside the class (e.g. sort Employee by ID). Comparator: custom sort order, implements compare(), supports multiple sort strategies, defined outside the class or as a lambda (e.g. sort by Salary, then Age). 
class Employee implements Comparable<Employee> {
  int id;
  public int compareTo(Employee o) { return Integer.compare(this.id, o.id); } // natural order
}
Comparator<Employee> bySalary = Comparator.comparing(Employee::getSalary);
employees.sort(bySalary.thenComparing(Employee::getAge)); // custom, chainable
Q55. How do you find max/min from a List, Set, or Queue?
✓ Asked ×1
Collections.max(collection) / Collections.min(collection) — using natural order or an optional Comparator argument. Stream equivalent: list.stream().max(Comparator.naturalOrder()).
Q56. Difference between Iterable and Iterator?
✓ Asked ×2
Iterable provides the iterator() method to obtain an Iterator (enables the for-each loop). Iterator actually traverses elements one by one using hasNext()/next() (and optionally remove()).
Q57. Can we modify a List/Map obtained via Collections utility methods?
✓ Asked ×1
A normal List/Map is fully mutable. Collections created via Collections.unmodifiableList() / unmodifiableMap() return a read-only view — any mutation attempt throws UnsupportedOperationException. (Also note List.of()/Map.of(), Java 9+, are immutable by construction.)
Q58. Methods in the Collections utility class?
✓ Asked ×1
sort(), reverse(), max(), min(), unmodifiableX(), synchronizedX(), emptyList(), singletonList(), shuffle(), frequency().
Q59. How would you design a custom List, Set, or Map?
✓ Asked ×1
Custom List → backed by a dynamic (resizable) array. Custom Set → backed internally by a Map, storing elements as keys against a shared dummy value (exactly how HashSet is built on HashMap). Custom Map → hash table + array of buckets + linked key-value nodes, with a hashing function to compute bucket index.

7Memory Management & JVM
Q60. Explain Stack and Heap memory.
✓ Asked ×2
Stack: stores method calls, local variables, method parameters, object references — per-thread, thread-safe, auto-cleared on method return. Heap: stores objects, arrays, instance variables — shared across threads, not thread-safe by default, managed by the GC. Method Area (Metaspace since Java 8): stores class metadata & static variables.
Q61. What are strong and weak references?
✓ Asked ×1
Strong Reference: a normal reference (Object o = new Object();) — GC will never collect the object while this reference is reachable. Weak Reference (WeakReference<T>): does not prevent GC — the referent can be collected as soon as no strong references remain (used in WeakHashMap, caching). There's also Soft Reference (collected only under memory pressure) and Phantom Reference (post-mortem cleanup, rare in interviews).
Q62. What are ClassLoader types? How does class loading work?
✓ Asked ×2
Java has three main ClassLoaders: Bootstrap (loads core Java classes, e.g. java.lang.*), Platform/Extension (loads Java platform libraries), and Application (loads application/classpath classes). Java loads classes via the Parent Delegation Model: a class-load request first goes to Bootstrap → Platform → Application (each parent gets first chance), followed by Loading → Linking (verify, prepare, resolve) → Initialization. This model prevents core classes from being overridden/spoofed by application code.
Q63. What is Metaspace?
✓ Asked ×1
Metaspace is the Java 8+ implementation of the Method Area — stores class metadata and static members. It replaced PermGen (which had a fixed size and was a common cause of OutOfMemoryError: PermGen space); Metaspace grows dynamically using native (off-heap) memory, bounded by available system memory unless -XX:MaxMetaspaceSize is set.
Q64. What is a Stop-The-World event?
✓ Asked ×1
A JVM pause during which all application threads are temporarily suspended, usually to let Garbage Collection run safely (so object graphs don't change mid-scan). Modern low-pause collectors (G1, ZGC, Shenandoah) minimize but don't eliminate STW pauses.
Q65. How would you analyze memory leaks?
💼 LinkedIn Asked
Take a Heap Dump and analyze with tools like Eclipse MAT (Memory Analyzer Tool) or VisualVM, looking for objects that remain reachable ("retained objects") but are logically no longer needed. Workflow: Heap Dump → GC Analysis → Eclipse MAT → find dominator tree / retained-size hotspots → trace back the GC-root reference chain keeping the leaked objects alive.
Q66. How can a Java app leak memory despite having Garbage Collection?
💼 LinkedIn Asked
GC only reclaims unreachable objects. A Java app leaks memory when objects remain reachable but are logically no longer needed — common causes: unbounded caches, static collections that keep growing, unclosed resources (streams/connections), listeners/callbacks never deregistered, or ThreadLocal values not cleared in pooled threads. Since these objects are still referenced, GC never collects them.
Q67. Can two objects have the same memory address in Java?
✓ Asked ×1
No. Two different live objects can never share the same memory address at the same time — every object created via new gets its own heap location (the JVM/GC may relocate objects during compaction, but never two live objects to the same address simultaneously).
Q68. Drawbacks of Garbage Collection?
✓ Asked ×1
Stop-The-World pauses — app threads paused during GC. CPU overhead — GC consumes CPU to identify/remove unused objects. Memory overhead — bookkeeping structures cost memory. Unpredictable execution — GC can trigger at any time, causing latency spikes. Performance impact — frequent or Full GC cycles slow the app under load.
Q69b. What is JIT compilation?
✓ Asked ×1
The JIT (Just-In-Time) Compiler is part of the JVM that converts frequently-executed ("hot") bytecode into native machine code at runtime, improving performance on repeated execution paths — instead of the interpreter re-interpreting the same bytecode every time. 
.class (Bytecode) → JVM Interpreter → [hot path detected] → JIT Compiler → Native Machine Code (cached & reused)
Senior-level add-on: HotSpot JIT uses tiered compilation (C1 for fast warm-up, C2 for aggressive optimization), plus techniques like escape analysis (stack-allocate objects that don't escape a method), lock elision/coarsening, and deoptimization (falls back to interpreted mode if an assumption made during optimization turns out wrong).
Q69c. What algorithms does the JVM use for garbage collection?
✓ Asked ×1
Mark-Sweep: mark live objects → remove unused ones (leaves fragmentation). Mark-Compact: mark live → remove garbage → compact remaining memory (removes fragmentation, costs more CPU). Generational Copying: copy/move live objects from one memory region (Young Gen survivor spaces) to another — cheap because most objects die young ("weak generational hypothesis"). Modern collectors: G1 (region-based, balanced default since Java 9), ZGC & Shenandoah (ultra-low-pause, mostly concurrent).
Additional JVM/GC Reference (not directly asked but essential background)
Young → Old GenerationNew objects start in Young Gen; if they survive multiple GC cycles, they're promoted to Old Gen.
Minor GC vs Major/Full GCMinor GC cleans Young Gen — fast. Major/Full GC cleans Old Gen — slower, more expensive.
OutOfMemoryErrorHeap is full AND GC cannot free memory (leak, oversized objects, unbounded growth).
StackOverflowErrorDeep or infinite recursion exhausts the (bounded, per-thread) Stack.
GC eligibilityReference set to null · out of scope · anonymous object · reassigned reference · island of isolation (mutually-referencing objects with no external reachable root).
GC RootsStarting points for reachability analysis — local vars on stacks, static fields, active thread objects, JNI references. Anything reachable from a root is "alive"; everything else is eligible for GC.
System.gc()Only a request, not a guarantee, that GC runs.
Handling Large Data Without OutOfMemoryError (common practical scenario)
Q70. How would you process a 5 GB CSV file without running into an OutOfMemoryError?
💼 LinkedIn Asked
Read and process the file line-by-line using a buffered stream (e.g. Files.lines() or BufferedReader) rather than loading the whole file into memory, processing each record and writing/aggregating results incrementally so memory usage stays roughly constant regardless of file size. 
try (Stream<String> lines = Files.lines(Path.of("data.csv"))) {
  lines.skip(1)                              // skip header
       .map(this::parseRecord)
       .forEach(recordProcessor::process);   // process & discard, one line at a time
}

Q71. Runnable vs Callable.
✓ Asked ×1
Runnable executes a task without returning a result — run() → no return, no checked exceptions. Callable<V> executes a task and returns a result — call() → returns V, can throw checked exceptions. Callable is used with ExecutorService.submit(), returning a Future<V>. 
Runnable r = () -> System.out.println("no result");

Future<String> f = executor.submit(c);
String result = f.get(); // blocks until done
Q72. What is a race condition, and how do you avoid it?
✓ Asked ×1
A race condition occurs when multiple threads try to access/modify the same shared resource simultaneously, resulting in inconsistent data (a "read-modify-write" that isn't atomic). Avoided using synchronization, locks (ReentrantLock), atomic classes (AtomicInteger), or concurrent collections (ConcurrentHashMap). 
// Unsafe: count++ is actually 3 steps (read, add, write) — not atomic
private int count = 0;
void increment() { count++; }        // RACE if called from multiple threads

// Fix 1: synchronized
synchronized void incrementSafe() { count++; }

// Fix 2: AtomicInteger (lock-free, CAS-based)
AtomicInteger safeCount = new AtomicInteger(0);
safeCount.incrementAndGet();
Q73. What is a deadlock? How do you solve/prevent it?
✓ Asked ×1
A deadlock is when two or more threads wait for each other's locks indefinitely (circular wait), so none can proceed. Prevented by maintaining a consistent lock acquisition order across all threads, using tryLock() with a timeout instead of blocking indefinitely, and avoiding nested locks where possible. 
// Thread-1: lock(A); lock(B);
// Thread-2: lock(B); lock(A);   ← reverse order = classic deadlock

Lock lock = new ReentrantLock();
if (lock.tryLock(5, TimeUnit.SECONDS)) {   // avoids indefinite block
  try { /* critical section */ }
  finally { lock.unlock(); }
}
Q74. What is volatile?
✓ Asked ×3
When one thread changes a volatile variable's value, other threads immediately see the updated value (visibility guarantee — no thread-local caching of the variable). However, volatile does not provide atomicity — volatile int count; count++; is still an unsafe read-modify-write across threads. 
private volatile boolean running = true;   // status flag — safe with volatile alone
// running = false; from another thread — visible immediately to the loop thread
Q75. Difference between volatile and synchronized?
✓ Asked ×1
volatile provides visibility only — used for status flags. synchronized provides both visibility and atomicity through locking — used for increment/decrement and other compound modifications.
Q76. What is ThreadLocal?
✓ Asked ×1
Each thread gets its own independent copy of the variable, so changes made by one thread are invisible to others — used for per-thread context like user session, correlation/request ID, or MDC logging fields. 
ThreadLocal<String> userContext = new ThreadLocal<>();
userContext.set("pranik");
userContext.get();
userContext.remove();   // IMPORTANT in pooled threads — else stale data/leaks across reused threads
Q77. What is concurrency vs concurrent?
✓ Asked ×1
Concurrency = the ability of a system to handle multiple tasks by making progress in overlapping time (not necessarily the exact same instant) — the concept of managing multiple tasks/threads together. Concurrent = the actual execution/progress of multiple tasks together. Parallelism (related) = tasks running truly simultaneously on multiple CPU cores.
Q78. How does multithreading work, and how many types of locks are there?
✓ Asked ×2
Multithreading creates multiple threads within a single process; the JVM creates the threads and the OS scheduler schedules/executes them on CPU cores. Threads share heap memory but have separate stacks. Lock types: 1) Intrinsic Lock (synchronized) — simple, automatic acquire/release. 2) ReentrantLock — manual lock, tryLock(), timeouts, more control. 3) ReadWriteLock — multiple concurrent readers, single exclusive writer. 4) StampedLock (Java 8) — adds optimistic read mode for better throughput.
Q79. Types of locks / difference between ReentrantLock, ReadWriteLock, synchronized?
✓ Asked ×1
synchronized (Intrinsic Lock): simple built-in JVM-managed locking, auto-release, no tryLock(). ReentrantLock: explicit lock offering tryLock() (non-blocking attempt), timeouts, and fairness. ReadWriteLock: improves performance by allowing multiple concurrent readers but only one writer at a time — ideal for read-heavy caches.
Q80. What is "how many types of lock" and what is double-checked locking?
✓ Asked ×2
Double-Checked Locking = two null checks + a synchronized block, used to create a thread-safe Singleton efficiently (avoids synchronizing on every call, only on first creation). Requires the instance field to be volatile to be truly correct — otherwise a thread could see a partially-constructed object due to instruction reordering. 
public class Singleton {
  private static volatile Singleton instance;   // volatile is essential here
  private Singleton() {}
  public static Singleton getInstance() {
    if (instance == null) {                        // 1st check — avoids locking every call
      synchronized (Singleton.class) {
        if (instance == null) {                    // 2nd check — avoids race during construction
          instance = new Singleton();
        }
      }
    }
    return instance;
  }
}
Q81. Thread-Safe Singleton.
✓ Asked ×3
A thread-safe Singleton ensures only one instance is created even under concurrent access. Approaches (from simplest to most idiomatic): 1) Eager initialization (static final field, JVM guarantees thread safety, but instance created even if unused). 2) Double-Checked Locking (lazy + efficient, see Q80). 3) Static Inner Holder Class (lazy, thread-safe via class-loading guarantees, no explicit locking needed — the cleanest classic approach). 4) Enum Singleton (simplest, inherently thread-safe and serialization-safe). 
public class Singleton {
  private Singleton() {}
  private static class Holder { static final Singleton INSTANCE = new Singleton(); }
  public static Singleton getInstance() { return Holder.INSTANCE; } // lazy, thread-safe, no locks
}
9Concurrency Toolkit — Executor, Locks, CompletableFuture, Sync Utilities
Q82. Explain the Executor Framework. Why is it preferred over manual thread creation?
✓ Asked ×2
The Executor Framework automatically manages and executes tasks using a thread pool instead of creating threads manually. It reuses existing threads, improving performance and reducing resource overhead. Manual new Thread() per task risks resource exhaustion in production — no pooling/reuse, no lifecycle management, no backpressure/queueing. 
ExecutorService ex = Executors.newFixedThreadPool(10);
ex.submit(task);
ex.shutdown();      // graceful — finishes queued tasks, rejects new ones
ex.shutdownNow();   // force — attempts to stop actively-running tasks too
Q83. Difference between execute() and submit()?
✓ Asked ×1
execute(Runnable) → runs a task, returns void (no way to get result/exception back). submit(...) → runs a task and returns a Future object, so you can retrieve the result, check status, or handle exceptions via get().
Q84. What is ExecutorService, and its lifecycle? Commonly used methods?
✓ Asked ×1
An interface in the Executor Framework that manages a pool of reusable threads, executes tasks, and controls their lifecycle. Lifecycle: Create → Submit → Execute → shutdown()/shutdownNow() → Terminate. Methods: execute() → run task; submit() → run task + return Future; shutdown() → graceful stop; shutdownNow() → force stop.
Q85. What is Future?
✓ Asked ×1
Future<V> represents the result of an asynchronous computation. Returned by ExecutorService.submit(); used to retrieve the result (get(), blocking), check task status (isDone()), or cancel the task (cancel()).
Q86. What is CompletableFuture?
✓ Asked ×1
An advanced Future that supports asynchronous, non-blocking execution and task chaining — you can compose pipelines of async steps, combine multiple futures, and handle errors declaratively, unlike plain Future which only offers a blocking get(). 
CompletableFuture<User> u = CompletableFuture.supplyAsync(() -> userService.getUser());
CompletableFuture<Order> o = CompletableFuture.supplyAsync(() -> orderService.getOrders());
CompletableFuture.allOf(u, o).join();     // run both API calls in parallel, wait for both

CompletableFuture.supplyAsync(this::callService)
  .thenApply(this::process)
  .exceptionally(ex -> "Fallback");          // supplyAsync → thenApply → thenCombine → exceptionally
Q87. What is the Fork/Join Framework?
✓ Asked ×1
A Java 7+ concurrency framework that recursively divides a large task into smaller subtasks (fork), executes them in parallel, then combines the results (join). Uses a ForkJoinPool with work-stealing — idle worker threads "steal" tasks from busy threads' queues to keep all cores utilized. Powers parallelStream() internally.
Q88. ForkJoinPool vs ExecutorService — when to use each?
💼 LinkedIn Asked
ForkJoinPool is designed for divide-and-conquer, recursively-splittable tasks using work-stealing — efficient for CPU-bound parallel computation (e.g. parallel sort, parallel streams). A regular ExecutorService just runs submitted tasks from a shared queue with a fixed/cached pool — better suited for independent, non-recursive tasks like I/O-bound work (DB calls, REST calls).

Q90. What happens if an exception is thrown inside a thread?
💼 LinkedIn Asked
If a Runnable running inside a Thread throws an uncaught exception, that thread terminates and the exception is passed to the thread's UncaughtExceptionHandler (the default one just prints the stack trace). It does not propagate to the calling thread and does not crash the JVM — so exceptions inside threads/executor tasks must be handled explicitly (e.g. wrap task logic in try-catch, or inspect Future.get() which re-throws as ExecutionException). 
Thread t = new Thread(() -> { throw new RuntimeException("boom"); });
t.setUncaughtExceptionHandler((thread, ex) -> log.error("Thread died: " + thread.getName(), ex));
t.start();  // main thread is unaffected; only this thread dies

10Java 8+ Features — Lambdas, Streams, Functional Interfaces
Q91. What is a Functional Interface? Its purpose? Can it have a default method?
✓ Asked ×2
A Functional Interface has exactly one abstract method. It can have any number of default, static, and inherited Object-class methods, and is commonly used with Lambda Expressions. Purpose: allows lambdas, makes code more concise/readable. @FunctionalInterface is an optional compiler check, not mandatory — but always add it anyway. 
@FunctionalInterface
interface Calculator {
  int calculate(int a, int b);         // the one abstract method
  default int triple(int x) { return x * 3; } // default methods allowed
}
Calculator add = (a, b) -> a + b;   // lambda implements the abstract method
Q92. What are Lambda Expressions? Why introduced?
✓ Asked ×1
Lambdas implement Functional Interfaces concisely, reducing boilerplate compared to anonymous inner classes. Introduced in Java 8 to reduce boilerplate, improve readability, and enable functional-style programming. 
// Before Java 8:
new Thread(new Runnable() { public void run() { System.out.println("run"); } }).start();
// Java 8+:
new Thread(() -> System.out.println("run")).start();
Q93. What are Streams? Can you pass a method reference in a lambda while using a Stream? How do method references work?
✓ Asked ×1
Streams process collection data declaratively using filter, map, collect, etc. Yes — method references are a shorter form of a lambda that just calls an existing method. 
list.stream().map(String::toUpperCase).forEach(System.out::println);
// String::toUpperCase  is shorthand for  s -> s.toUpperCase()
// System.out::println  is shorthand for  s -> System.out.println(s)
Q94. Difference between map() and flatMap()? Real use case?
✓ Asked ×1
map() transforms each element into another element, 1-to-1 (e.g. List<Employee> → List<List<Skill>>). flatMap() transforms elements and flattens nested collections into a single stream (e.g. List<Employee> → List<Skill>, merging every employee's skill list into one flat stream). 
List<Skill> allSkills = employees.stream()
  .flatMap(e -> e.getSkills().stream())   // flattens List> into Stream
  .distinct()
  .collect(Collectors.toList());
Q95. What is Optional? Why is it not recommended as a class field?
✓ Asked ×2
Optional<T> represents an optional value and avoids NullPointerException. Best used as a method return type, not as a class field or method parameter — using it as a field adds serialization complications and doesn't play well with frameworks/JPA entities; it was specifically designed for the "return type that may be absent" use case. 
public Optional<User> findById(Long id) {

}

Q96. What are default methods and static methods in interfaces?
✓ Asked ×2

interface Vehicle {

Q98. Explain the Stream pipeline. Difference between source, intermediate, and terminal operations?
💼 LinkedIn Asked
A Stream Pipeline = Source → Intermediate Operations → Terminal Operation. Source provides data (a collection, array, generator). Intermediate ops (filter, map, sorted) prepare/transform data and are lazy — nothing executes until a terminal op is invoked. Terminal ops (collect, forEach, reduce) execute the whole pipeline and produce the final result. 
list.stream()                         // source
    .filter(x -> x > 10)              // intermediate — lazy
    .map(x -> x * 2)                  // intermediate — lazy
    .collect(Collectors.toList());    // terminal — triggers execution
Q99. What are Collectors, and what do they do internally?
✓ Asked ×1
Collectors are utility classes used to collect/transform processed stream elements into a final result — List, Set, Map, String, or grouped data. Internally: they create a result container (via a Supplier), accumulate stream elements into it (via a BiConsumer), and return the final combined result (via a Function/BinaryOperator for parallel merges). 
Map<String, List<Employee>> byDept =
  employees.stream().collect(Collectors.groupingBy(Employee::getDept));
double avgSalary = employees.stream().collect(Collectors.averagingDouble(Employee::getSalary));
Q100. Why would you use parallel streams over a normal (sequential) stream?
💼 LinkedIn Asked
Parallel streams split the data across multiple threads (using the common ForkJoinPool) to process elements concurrently, improving throughput for large datasets with CPU-intensive operations. For small collections, or I/O-bound/order-sensitive operations, the overhead of thread coordination can make parallel streams slower than sequential — always measure before switching, don't default to parallel for "performance." 
list.parallelStream().map(this::heavyComputation).collect(Collectors.toList());
// AVOID parallelStream() for: DB calls, external API calls, small collections
Q101. Streams vs traditional loops — when would you prefer one over the other?
💼 LinkedIn Asked
Streams favor declarative, functional-style code (filter/map/collect) that's often more concise and easily parallelizable, but traditional loops give finer control, can be more performant for simple iteration, and are easier to debug step-by-step (breakpoints inside a lambda chain are awkward). Prefer streams for data transformation pipelines; prefer loops for simple iteration or complex branching control flow.

Q105. What design patterns have you used? (10–12 patterns overview)
✓ Asked ×1
Design Patterns are reusable solutions to common software design problems, categorized into Creational (create objects), Structural (connect objects), and Behavioral (communicate between objects). Q107. How do you debug a production issue?
✓ Asked ×1
1. Understand the issue → 2. Check logs → 3. Reproduce if possible → 4. Identify root cause → 5. Check recent changes (deployment/code/config) → 6. Verify DB/external APIs → 7. Check JVM & infrastructure (CPU, memory, threads — thread dump/heap dump) → 8. Apply fix → 9. Test in lower environment → 10. Deploy & monitor.
Q108. How do you improve the performance of existing code?
✓ Asked ×1
1. Identify the bottleneck → 2. Profile the application (VisualVM/JProfiler/JFR) → 3. Optimize the code → 4. Optimize database queries/indexing → 5. Reduce external API calls → 6. Introduce caching → 7. Improve concurrency (if needed) → 8. Measure before & after. Data-driven, not guesswork.
Common Interview Problem-Solving Patterns (Practical Reference)
Thread-safe Cache
ConcurrentHashMap + computeIfAbsent() to avoid duplicate loads; add TTL/LRU eviction or use Caffeine/Ehcache/Redis in production.
Remove Duplicates from a List
new HashSet<>(list) (order lost) · new LinkedHashSet<>(list) (order kept) · list.stream().distinct().collect(...) (Java 8 way)
Top-N Frequent Elements
Count via HashMap<T,Integer> → push into a PriorityQueue (max-heap) by frequency → poll top N
Processing Millions of Records
Pagination/streaming/batch processing, bulk DB ops + parallel processing where safe — avoids OutOfMemoryError, minimizes memory footprint

Core Java / OOP / Collections
✓JDK = JRE + Dev Tools · JRE = JVM + Libraries · JVM = executes bytecode
✓== compares reference/value; .equals() compares content
✓Integer cache: -128..127 cached → == true in range, false outside
✓Encapsulation/Abstraction → Data Hiding / Hide Implementation
✓Overloading = compile-time (same class, diff signature); Overriding = runtime (parent→child, @Override)
✓No multiple class inheritance → avoids Diamond Problem; interfaces allow it
✓Abstract class: partial impl, single inheritance. Interface: contract, multiple inheritance
✓Constructors cannot be static/final — only access modifiers allowed
✓String immutable → security, thread-safety, pool reuse, cached hashCode
✓StringBuilder (fast, not thread-safe) vs StringBuffer (sync, thread-safe)
✓ArrayList: fast random access, slow mid insert/delete. LinkedList: reverse
✓HashMap: hashCode()→bucket, equals()→exact entry; Java8 treeifies buckets >8 nodes
✓HashMap resize: entries > capacity×0.75 → doubles array, full rehash
✓ConcurrentHashMap: bucket/node locks + CAS, no null key (ambiguity risk)
✓Fail-Fast (ArrayList/HashMap) throws CME; Fail-Safe (COW/ConcurrentHashMap) iterates a snapshot
✓Equal objects → same hashCode (required). Same hashCode → not necessarily equal
✓Custom HashMap key → override equals()+hashCode(); keep fields immutable
✓Collections.unmodifiableList/Map() → read-only view; source list still mutable directly
✓Cloneable is a marker interface (no methods)
✓Comparable = natural order, inside class. Comparator = custom order, outside/lambda
Memory / JVM
✓Stack: method calls/locals, thread-safe. Heap: objects, shared, GC-managed
✓Metaspace (Java 8+) replaced PermGen — grows dynamically, off-heap
✓ClassLoading: Bootstrap → Platform → Application (Parent Delegation)
✓Two live objects never share a memory address
✓Strong ref → GC can't collect. Weak ref → GC can collect anytime
✓Memory leak = still-referenced but logically-dead objects (caches, listeners, static collections, ThreadLocal)
✓Minor GC = Young Gen, fast. Major/Full GC = Old Gen, slow
✓Stop-The-World = all app threads paused during GC
✓System.gc() only requests, never guarantees, collection
✓GC algorithms: Mark-Sweep, Mark-Compact, Generational Copying; modern: G1/ZGC/Shenandoah
✓Analyze leaks: Heap Dump + Eclipse MAT/VisualVM → retained objects
✓Large files: stream line-by-line (Files.lines/BufferedReader), never load whole file
Multithreading / Concurrency
✓Concurrency ≠ Parallelism (overlap vs simultaneous)
✓Thread: NEW→RUNNABLE→RUNNING→(BLOCKED/WAITING/TIMED_WAITING)→TERMINATED
✓Prefer Runnable/Callable over extending Thread
✓Race Condition = unsynchronized shared-state read-modify-write
✓volatile = visibility only, NOT atomicity
✓Atomic classes use CAS — lock-free thread safety
✓ReentrantLock > synchronized: tryLock(), fairness, interruptible
✓Deadlock = circular wait on locks → prevent via consistent lock ordering
✓wait() releases lock (needs synchronized); sleep() keeps lock
✓Avoid new Thread() in enterprise code — use ExecutorService/ThreadPoolTaskExecutor
✓CPU-bound pool size = cores+1; I/O-bound = cores×(1+wait/compute)
✓parallelStream() uses common ForkJoinPool — avoid for I/O-bound work
✓CompletableFuture > Future: non-blocking, chainable, combinable
✓CountDownLatch = one-time; CyclicBarrier = reusable
✓Semaphore = limit N concurrent threads (DB pool, rate limiting)
✓ThreadLocal = per-thread isolated data; always .remove() in pooled threads
✓@Async fails on self-invocation — Spring AOP proxy bypassed
✓Uncaught exception in a thread → UncaughtExceptionHandler, doesn't crash JVM or propagate to caller
✓Kafka: partitions ≥ consumers; extra consumers idle
✓Troubleshooting: thread dump for deadlock/blocking, heap dump for memory
Java 8+ / Exceptions
✓Functional interface = exactly 1 abstract method (+ default/static allowed)
✓Stream: Source → Intermediate (lazy) → Terminal (triggers execution)
✓map() = 1:1 transform; flatMap() = transform + flatten
✓Optional → best as return type, not field/param
✓Parallel streams: good for CPU-heavy large data; risky/slower for small/I-O-bound
✓Checked exceptions → compile-time, recoverable (IOException, SQLException)
✓Unchecked exceptions → runtime, programming errors (NPE, ArithmeticException)
✓finally always runs; return/throw in finally overrides try's outcome
✓Never catch Throwable; never swallow exceptions silently
✓Try-with-resources needs AutoCloseable; compiler auto-generates the finally/close()
✓Custom exceptions extend RuntimeException for Spring Boot business errors
✓@RestControllerAdvice + @ExceptionHandler = centralized JSON error handling
✓DRY / KISS / YAGNI → Don't Repeat / Keep Simple / Build Only What's Needed
